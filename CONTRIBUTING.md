# Contributing to MkLume

Thank you for your interest in contributing to MkLume.

MkLume is an open-source, local-first desktop workspace for creating, editing, previewing, and managing MkDocs Material documentation.

The project is created by Enrique Cal — ECal Studios.

## Before contributing

Please keep in mind:

- MkLume is built for MkDocs Material projects.
- MkLume is not affiliated with MkDocs, Material for MkDocs, Git, GitHub, or their maintainers.
- GitHub Issues are the main place for bug reports, feature requests, and questions.
- Ko-fi is only for supporting development through donations, not for technical support.

Official documentation:

https://www.ecalstudios.com/mklume/

Donation link:

https://ko-fi.com/ecalstudios

## Ways to help

You can help by:

- Reporting bugs
- Suggesting improvements
- Improving documentation
- Testing MkLume on different systems
- Sharing clear feedback about the user experience
- Opening pull requests for small, focused improvements

## Reporting bugs

Before opening a bug report, please check if a similar issue already exists.

A good bug report should include:

- Your operating system
- MkLume version
- What you were trying to do
- What happened
- What you expected to happen
- Steps to reproduce the problem
- Screenshots or logs if useful

Please do not include private files, passwords, tokens, API keys, or personal data in bug reports.

## Suggesting features

Feature requests are welcome.

A good feature request should explain:

- What problem the feature solves
- Who it helps
- How you imagine it working
- Whether there is a workaround today

Please keep feature requests focused and practical.

## Pull requests

Pull requests are welcome, but please keep them focused.

Good pull requests are usually:

- Small
- Easy to review
- Clearly explained
- Related to an existing issue when possible
- Tested locally before submission

Please avoid large rewrites without discussion first.

## Development setup

MkLume is built with:

- Tauri 2
- React
- TypeScript
- Rust

More detailed development instructions will be added as the project matures.

## Code style

Please aim for code that is:

- Clear
- Maintainable
- Easy to understand
- Consistent with the existing project structure

Avoid unnecessary complexity.

## Documentation changes

Documentation improvements are very welcome.

The canonical documentation is hosted here:

https://www.ecalstudios.com/mklume/

If you update documentation-related files in the repository, please make sure the wording stays consistent with the official MkLume branding.
